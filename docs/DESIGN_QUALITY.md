# Design Quality Contract

This review applies the seven principles in the user-supplied video transcript to Portal’s product template, themes, and reusable controls. Runtime theme objects remain canonical; this is a refinement of the established system. It is not a claim that a reusable template can guarantee every future screen’s content or focal point.

## Reusable Motion Ownership

Theme objects → resolveThemeOverlayMotion / compileTheme → semantic CSS + usePresentationMotion → Modal, AlertModal, SheetPanel, MobileNavigationMenu, popovers, and ToastStack. `useListMotion` owns interruption-aware layout movement; a separate toast child owns entrance/exit so the two transforms do not fight. `useSheetDrag` owns direct manipulation and cleanup; PresentationProvider owns queues, lifetimes, and resolved exit fallbacks.

Use the [theme profile API](THEMING.md#overlay-motion-profiles), [UI system](UI_SYSTEM.md), and [behavior contract](../UX-CONTRACT.md). The local Motion specimen demonstrates six positions, a three-toast sequence, custom timing, and a bottom sheet. Appearance exposes persisted entrance/exit overrides and reset.

## Review Future Screens

Identify the main task and make its action clearly dominant. Check the loaded spacing rhythm and grouping. Build type hierarchy with weight/foreground before size. Use accent and semantic status colors purposefully. Replace generic placeholder copy with honest domain content. Compare corners, inset geometry, borders, shadows, icon alignment, and focus states with shared components. Confirm that movement starts from the relevant trigger/edge, responds to interruption, closes promptly, and becomes still under Reduced Motion.

Check at a small laptop and a narrow phone width, in light/dark mode, with keyboard and reduced motion. Critical errors stay inline; transient feedback supplements them. See [verification evidence](VERIFICATION.md) for actual checks and known limits.
